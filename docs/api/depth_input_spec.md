# 深度画像 (デプスマップ) の仕様 — フロント実装向け

> 10/1 定例で「深度画像はフロント側で作る」と決まったので、生成側 (岸) が前提にしている形式をまとめる。
> この形式から外れると、器が平たい板になる・形がずれる、といった失敗が出る (どれも 9/24〜9/26 に実測済み)。
> 生成 API に深度画像を渡す口は v5 worker で新設する (この文書の最後を参照、仕様は追って確定)。

## 1. 形式

| 項目 | 値 |
|---|---|
| サイズ | 1024 × 1024 px (正方形) |
| 色 | グレースケール (RGB 3ch に同じ値を入れた PNG でも可) |
| 向き | **近い = 白 (255)、遠い = 黒 (0)** |
| 背景 | 黒 (0) |
| 器の値域 | **器の中だけで 0〜255 をいっぱいに使う** (器の輪郭 ≒ 0、いちばん手前 = 255)。背景や床と一緒に正規化しない |
| 視点 | **ほぼ水平の正面** (検証済みは真正面と、やや上から = 俯角 約 13°)。俯角 約 24° の見下ろしは失敗 |
| 配置 | 中央、上下左右に余白。器の面積は画面の 15〜45% (検証済みの範囲) |

これは v5 で形の追従を確かめた形式 (筒・鉢・立方体のプローブ) と同じ。床を入れた形式 (3 を参照) も検証済みだが、
フロントで作るのは床なしでよい。

**いちばん大事なのは「器の中の階調」**。器の中で値がほとんど変わらない (真っ白な塊になる) と、平面の絵として描かれる。
検算として、器の領域 (値 > 0) の標準偏差が **40 以上**あること (下のサンプルは 50〜74、失敗例は 4)。

## 2. 作り方 (2 通り、どちらも検証済み)

### A. 回転体近似 — 一筆書き・ろくろ形のプリセット向け

器を「ろくろで挽いた軸対称の形」とみなすと、正面から見た深度は輪郭だけから計算で決まる。
深度推定モデルより確実 (線画や素焼きの単色の器は、推定モデルだと平たくなりやすい)。

```
各行 y について:
  輪郭の左端 x0・右端 x1 → 半径 r = (x1 - x0) / 2、中心 cx = (x0 + x1) / 2
  r_max = 全行の r の最大値
  器の内側の画素 x について:
    t = (x - cx) / r
    d = sqrt(1 - t²) * (r / r_max)        # 0〜1。中心ほど手前、細い首は低め
  器の外 = 0
最後に 0〜255 に伸ばす: v = d / max(d) * 255
```

- `r / r_max` を掛けるのは、口元のような細い部分を手前に出しすぎないため (物理的な関係を保つ)
- 参考実装 (Python): `scripts/build_depth_maps.py` の `depth_from_lineart()` と、`scripts/make_probe_depths.py`

### B. 3D モデルから焼く — 埴輪・招き猫など回転体でない形向け

形の 3D データ (または素焼き画像を作ったときの 3D) があるなら、Blender 等でカメラ距離を焼くのが最も正確。

- カメラは水平。器 (物体) の距離範囲だけで 0〜255 に正規化する (背景や床と同じ範囲で正規化しない)
- 参考実装: `scripts/demo_glaze_vessel.py` (`KESHIKI_DEMO_DEPTH=1` で距離をエミッションとして焼く)

### C. 素焼き画像から深度推定 (未検証)

3D が無い複雑な形は、深度推定モデル (Depth Anything V2 など) で素焼き画像から推定することになる。
**出力はそのまま使わず、物体のマスクで切り出してから 1 の形式 (物体の中を 0〜255、背景 0) に正規化し直す**こと。
推定モデルの出力は背景や床まで含めた範囲で正規化されていて、物体の階調が潰れていることが多い。

## 3. 床を入れるか

- 確定版 (`depth_comp_s60`) は **床あり**: 器を 60〜255、床を 0〜59 に別々に割り付けて合成している
  (器と床を同じ範囲で正規化すると、器の階調が潰れて平面になる = 実測 std 49.6 → 4.4)
- 床なし (背景 0) でも、caption 側の環境語 (窓辺の光・木の卓など) だけで空間が作れることは確認済み
- → **フロントで作るのは床なしで十分**。床が要るかは生成側で判断する

## 4. やってはいけないこと (実測で失敗したもの)

| やったこと | 結果 |
|---|---|
| 器と床を同じ範囲で正規化 | 器が真っ白な塊になり、平面の絵になる |
| 強い見下ろし (俯角 約 24°) | 床の中間調が「器を囲む輪」(ガラス枠・装飾リング) として描かれる |
| 白黒を逆にする (近い = 黒) | 形が反転する。モデルの規約は近い = 白 |
| 深度と別に参照画像 (素焼き画像など) を一緒に渡す | 色が参照に引っ張られて釉薬が乗らない・形も参照側に戻る |

## 5. 背景の切り抜きについて (10/1 定例の論点)

「深度画像の深いところ (背景 = 0) を抜けば器だけ切り抜ける」は**そのままでは不十分**。
生成された器の輪郭は深度の輪郭から数 px〜十数 px ずれることがある (10/5 実測: 肩の部分で背景の窓が深度の内側に入り込んだ)。
深度でそのまま抜くと、縁が欠けるか背景が細く残る。
対策は v5 worker の検証で決める予定 (候補: 生成画像側で前景を切り出すモデルを使う / 深度のマスクを少し膨らませてぼかす / 背景を無地にする caption で生成する)。

## 6. 生成 API への渡し方 (予定)

v5 worker で、`input` に深度画像を受け取る口を新設する。想定:

```json
{
  "input": {
    "depth_png": "<base64 PNG, 1024x1024>",     // または
    "depth_preset": "vase_01",                    // サーバー側に置いたプリセット深度の ID
    "...": "釉薬パラメータ (仕様は v5 worker で確定)"
  }
}
```

確定したら `serverless_api.md` に v5 の節を追加して知らせます。

## 未検証のこと (生成側で確認予定)

- 埴輪・招き猫など回転体でない複雑な形 (v5 で確認したのは筒・鉢・立方体・通常の壺)
- 手描きの一筆書きから作った深度を v5 に通したとき (FLUX.1 では成立済み)
- 床なし深度 + 窓辺の環境語の組み合わせを、9 釉薬そろえて v5 で見たとき (形のプローブは 3 釉薬のみ)
